# 阶段四：撰写审查意见答复

分工版中，Terra只可在已冻结`active_snapshot_id`和主策略上生成内部条件性草稿。权利要求修改、活动集合切换、旧分析失效、NB/IS重算和`recalculation_gate`由Sol发起并审核；代理师确认保护范围取舍后方可形成对外审核稿。

## 目的

基于前三阶段的 MBSE 模型（阶段一）、事实审计报告（阶段二）和追溯链分析报告（阶段三），撰写审查意见答复或复审意见陈述书。

## 核心原则

1. **证据锚定原则**：每个论证点必须有阶段二或阶段三的证据支撑。在论证中引用阶段二的核实结论编号（如 F-01）和阶段三的断裂点编号（如 C-01-B1）。
2. **不引入新事实原则**：答复中不得出现前三阶段未建立的、未经核实的事实主张或技术断言。
3. **逐点回应原则**：审查意见中提出的每一个问题都必须得到回应，不得遗漏。
4. **技术路线优先原则**：论证组织以修改后权利要求的技术路线为主线，而非以审查员的驳回逻辑为主线。

## 前置输入确认

- [ ] 阶段三：审查员组合路径追溯链映射、结合可行性分析表、追溯链分析报告
- [ ] 最新的权利要求修改文本（如用户未提供，使用当前授权/公开文本）
- [ ] 用户指定的术语、特征顺序和论证优先级（如有）
- [ ] 问题—处理动作矩阵已建立，审查意见问题总数与矩阵行数一致
- [ ] 当前权利要求有唯一版本 ID，且所有修改事件、支持依据和 `supersedes` 关系已回写

## 论证撰写指南

### 先确定处理动作

撰写前，为每个 `office_action_issue` 选择唯一主处理动作：

| 条件 | 主处理动作 | 输出要求 |
|---|---|---|
| 事实认定正确，无需改变范围 | 认可 | 简要确认，不制造伪争议 |
| 事实或技术启示缺少证据 | 争辩 | 给出原文位置、偏差与追溯断点 |
| 表达可改进且范围代价可接受 | 修改 | 列出修改前后、支持依据和范围影响 |
| 从属特征或方案价值低于程序成本 | 删除 | 说明删除对引用关系与保护范围的影响 |
| 单一性/保护策略需拆分 | 分案 | 标记需客户确认的对象和期限 |
| 事实、日期或客户意图不足 | 补充核验/客户确认 | 标记 `Q`，不得宣称已可提交 |

主处理动作之外可记录辅助动作，但不得出现同一问题在不同文件中被同时标记为“认可”和“否认”。

### 权利要求版本重计算门

对每个新 `CLM` 版本，依次重新确定：

`CLM 文本 → 必要 CF/REL → 区别特征 → 技术效果边界 → 实际技术问题 → NB/IS → 答复论证`。

任一环节仍引用旧 `CLM` 的区别特征、问题或结论时，回退到阶段一/三重新计算。

### 事实陈述

使用阶段二中核实为 `✅ 支持` 或 `⚠️ 部分支持` 的事实：

> 如审查员所述，D1 公开了……（见事实核实表 F-01，✅ 支持）。

### 反驳论述

使用阶段二中核实为 `❌ 不支持` 或 `🚫 无记载` 的事项：

> 审查员认为"……"（审查意见第 X 页第 Y 段）。但经核实，D1 原文记载为"……"（D1 [00XX]），审查员的认定与原文存在实质性偏差，具体表现为……（见事实核实表 F-02，❌ 不支持）。

### 技术启示反驳

使用阶段三的追溯链分析：

> 审查员主张将 D2 的摩擦驱动方式应用于 D1 的链条结构（组合 C-01）。但从追溯链分析可见（见追溯链分析报告 §2.1），D1 的追溯链在 B1 节点（链轮啮合驱动链条沿导轨行进）处发生断裂——若改为摩擦驱动，D1 不再具有啮合驱动力，其原有的"链轮啮合驱动"这一行为无法执行。同时，D1 与 D2 在驱动界面和接口维度存在不兼容（见结合可行性分析表 C-01），二者不具备结合的技术基础。

### 不兼容论证

根据当前 mode 选用对应的域论证模式文件：

- **mechanical** → `references/domain-argument-patterns-mechanical.md` 模式 2「对比文件不兼容」
- **biochemical** → `references/domain-argument-patterns-biochemical.md` 模式 1「组分不兼容」或模式 2「工艺条件冲突」
- **electronic-communication** → `references/domain-argument-patterns-electronic-communication.md` 模式 1「数据流断裂」或模式 2「协议/接口不兼容」

**通用论证模板**：

> 对比文件 D1 的 [方案/体系] 以 [前提条件 A] 为基础，而对比文件 D2 的 [教导/方案] 以 [前提条件 B] 为前提。将 D2 的方案应用于 D1 时，[前提条件 A] 与 [前提条件 B] 之间存在不可调和的冲突，具体表现为 [冲突细节]。因此，本领域技术人员没有动机作出此种组合。

### 整体协同效果

> 上述区别技术特征并非彼此孤立的零部件替换，而是通过……位置关系/连接关系/运动关系共同构成……技术手段。各组区别特征协同作用，共同实现……技术效果。将任一组区别特征剥离后，其余特征将无法独立实现上述效果。

## 从属权利要求处理

- 从属权利要求必须先沿每条合法引用路径展开完整评价对象；不得只评价其新增限定；
- 即使OA未单独攻击，也必须建立 `inherited` 或 `no_separate_issue` 的NB/IS记录，明确继承路径、附加限定和为什么无需单独争议；
- OA单独攻击的从属权利要求使用 `full` 记录并在对外答复中作对应论证；
- 不得将已纳入修改后独立权利要求的特征重复作为从属权利要求的贡献。
