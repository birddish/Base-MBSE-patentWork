# OA活动版本、分析快照与重算门

本文件是阶段零、三、四、五共用的执行规范；对象字段以 `oa-evidence-pack-schema.md` 为准。

分工版同时执行`oa-context-and-parallel-contract.md`。只有Sol可以发起活动权利要求集合/主策略变更和重算事务；Luna/Terra只能输出候选红线或条件性草稿，不能激活新集合。

## 1. 阶段零冻结前清单

1. 建立完整OA问题注册表，为每项问题生成稳定指纹；
2. 将文献事实状态与新颖性/创造性法律资格分轴登记；
3. 列出原始、候选、活动、废止权利要求集合；
4. 只有集合身份和修改支持均确定时，才写唯一 `active_claim_set_id`；
5. 材料冲突或缺失使用 `Q`，不以“较高/较低风险”代替未知。

## 2. 阶段三快照协议

阶段三开始前必须冻结活动集合、经存在性/顺序/无环性/文本一致性核验的依赖图、全部引用路径、文献双轴资格和唯一主策略。关系不明时阻断，禁止生成虚假`SELF`路径。冻结后才生成TA、NB、IS及核心区别链。事实或策略改变时，不修改旧快照内容；新建快照并使旧快照失效。

## 3. 修改影响闭包

对任一修改项 `c`，影响闭包为：

```text
Closure(c) = {c}
             ∪ 全部直接和间接引用后代
             ∪ 因编号、引用路径或保护主题改变而变化的权项
```

闭包内每项权利要求按每条有效引用路径重新展开，并重新生成TA。局部闭包由真实依赖图计算，不等同全部活动权利要求；全案NB/IS完整覆盖另设独立检查。不能只给修改独立项重算而把从属项视为自然继承。

修改事务开始时冻结依赖旧`active_snapshot_id`的并行任务并写入失效账本。已完成的旧快照产物只保留为历史，不得合入活动答复。

## 4. NBComplete与ISComplete执行检查

- `NBComplete(V)`：活动集合V中每个权利要求、每条有效引用路径均具有所需的单文献NB卡和唯一汇总对象；无资格、`Q`或`conditional`文献不能支撑确定结论；不适用时也要有结构化`no_separate_issue`记录。
- `ISComplete(V)`：同一覆盖集合中每条路径都有 `full/inherited/no_separate_issue` 之一，且明确文献资格、区别链、技术启示状态与结论确定性。

二者缺一，`recalculation_gate.passed=false`。

## 5. 原子事务回滚条件

出现以下任一情况即停止定稿：

- `supersedes` 或修改事件缺失；
- 支持依据为 `Q`；
- 活动集合、快照或主策略不是唯一；
- 闭包内NB/IS覆盖不全；
- 仍存在旧快照的活动NB/IS/RT；
- 活动答复追溯没有全部切换至新快照；
- 决定性Q进入确定风险、覆盖结论或闭合组合路径。
- `ineligible/not_applicable/Q/conditional`文献进入确定NB/IS；
- 活动NB/IS违反复合唯一键，或同一路径缺少唯一汇总结论对象。

停止后保留内部条件性草稿，列明具体缺口；不输出“定稿”“可提交”或无条件肯定结论。

## 6. 阶段五五方一致性

从同一 `active_snapshot_id` 出发逐项核对：

```text
活动权利要求集合
↔ 问题注册表
↔ NB/IS与核心区别链
↔ response_trace和对外答复段落
↔ content/submission就绪状态
```

任何一方对象、文献资格、处理动作或状态不一致，均不得通过审计。

分工版另核验任务上下文、交接包和活动快照一致；`input_snapshot_hash`不匹配的产物不得参与五方一致性。
