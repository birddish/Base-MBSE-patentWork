# 专利检索工作流

将输出定位为内部一次调查，不构成法律意见。重要的 FTO、无效或侵权结论必须建议由专利代理师、律师或专业检索机构复核。

## 启动与存档

1. 若工作区存在 `docs/patent-search/`，检查未完成案件；读取其已同意的成果物与 `sources/`，询问用户是否继续。
2. 对新案件确认模式、调研对象、判断基准日、权利判断地域、语言和交付物。默认将中国（CN）、美国（US）、日本（JP）、韩国（KR）、欧洲专利（EP）和 PCT 国际申请（WO）合并设为六法域必查范围。先建立中文、英文、日文、韩文、法文和德文关键词块，并结合 IPC/CPC、FI/F-term 等适用分类，在全球数据库中执行不限定法域的统一检索；六法域用于最终覆盖核验，不等于默认分别执行六次法域检索。仅当统一检索的命中量超过工具一次性完整、稳定提取的上限，且分页或分批提取仍不能可靠取得全部结果时，才考虑按法域拆分，并记录命中量、工具上限、已尝试的分页/分批方式及拆分理由。不得仅因操作习惯或语言差异上来就按法域拆分。仅在用户明确要求缩减范围，且成果物记载缩减理由、未查范围及其影响时，方可省略任何必查法域。建议一个简短的 kebab-case 案件名。
3. 在 `docs/patent-search/<案件名>/` 创建并声明 `delivery_profile=quick|standard|formal`；新案件默认 `standard`。交付要求、状态、结论权限和风险登记以 [delivery-profiles.md](references/delivery-profiles.md) 为准。不得把下载或本地保存专利 PDF 设为完成条件。
4. 将用户提供的检索结果标为“用户提供”。公开号/专利号经官方或可信数据库书目解析后可进入候选清单；对拟作为核心对比文件或支撑实质结论的文献，必须再通过 MCP 或可信全文渠道核对权利要求、说明书或附图，无需取得本地 PDF。

## 模式

| 模式 | 重点 | 模式专用指南 |
|------|------|-------------|
| 查新检索 | 发明特征与全体已公开文献的披露对比。 | [mode-novelty.md](references/mode-novelty.md) |
| 无效检索 | 目标权利要求与基准日前公知文献的对比。 | [mode-invalidity.md](references/mode-invalidity.md) |
| FTO(自由实施调查) | 对用户指定权利地域内存续或审查中的权利与产品规格逐项对比；六法域必查范围中的其他地域文献仍用于现有技术、同族及风险线索检索，不据此直接作出该权利地域的侵权结论。 | [mode-fto.md](references/mode-fto.md) |
| 专利态势分析 | 定义可代表的文献集合，分析分类、申请人和时间趋势。 | [mode-landscape.md](references/mode-landscape.md) |

不要混淆查新检索（失效文献也可作为证据）与 FTO（只关注可能有效的权利）。

## 五个阶段

1. **检索方案设计**：确定模式、范围、基准日，并将发明、目标权利要求或产品规格拆分为技术特征。对于涉及多组件、多功能、多步骤的复杂系统，可选使用 `mbse-patentability-analysis` 技能（`mode=search`）进行轻量 MBSE 三视图建模（F/S/B），系统化驱动后续检索块生成。
2. **检索策略**：从跨法域近似文献反查 IPC/CPC，并按日本文献检索需要补充 FI/F-term；建立中文、英文、日文、韩文、法文和德文关键词块、同义词/表述变体及分类式。对每条正式查询只做一次语法、范围和基准日校验，随后优先执行全球统一检索并保存原始结果。已知 benchmark 用于发现漏检风险；未命中时登记待办并补检，不阻断首次执行。不得预先按法域拆式；只有出现提取异常或在最终主张完整覆盖时，才核验分页/分批或准备法域拆分式。
3. **本检索与筛选**：先执行全球统一检索，立即保存最小运行记录（数据库、检索式、命中数、日期、结果文件、截断/异常状态），再按标题、摘要、分类和书目信息筛选并核验核心候选。仅在工具提示截断、结果不稳定、异常空白或最终报告主张完整提取时，补作分页/分批证明；只有确认无法完整稳定提取时才按法域拆分。`检索策略与日志.xlsx` 的汇总、美化和报告逐项一致性检查延后至阶段5。合并去重时保留公开国别、同族和来源查询。MCP 读取不要求形成或保存本地 PDF。
4. **对比分析**：为每件核心文献建立要素对比表或权利要求对照表，并标明 MCP 返回内容中的权利要求编号、段落或附图位置。非核心文献可仅保留号码及相关性线索。缺少本地 PDF 不影响对比分析；缺少可定位的 MCP/可信全文内容则不得将该核心文献标记为"充足"。
5. **报告**：最终复核所有列入成果的公开号/专利号及来源，并对核心文献记载 MCP/可信全文的证据位置，生成报告与可独立阅读的 `report.md`。最终附件默认只需号码清单和报告，不要求附带或本地保存公报 PDF。

开始案件时先读取 [delivery-profiles.md](references/delivery-profiles.md)，再读取 [stage-templates.md](references/stage-templates.md) 和当前模式指南。`quick/standard` 可将阶段 1–3 合并为单个 `search_run.md/json`；`formal` 按五阶段完成。阶段 2–3 按需读取 [cn-search-guide.md](references/cn-search-guide.md) 和 [search-guide.md](references/search-guide.md)；阶段 5 或正式交接时读取 [handoff-templates.md](references/handoff-templates.md)。复杂系统案件才建议在阶段 1 委托 `mbse-patentability-analysis`（`mode=search`）。

## 推进与审计分层

- **运行门**：检索式可执行、模式和基准日无冲突、范围未越界，即可运行并保存原始结果；不等待工作簿美化、分页哈希或全部 benchmark 命中。
- **条件通过**：原始结果已保存且待办已记录时，可进入核心文献筛选与全文核验。benchmark 未命中、异常法域分布或疑似截断须标注为高风险待办，不得被写成已完成覆盖。
- **结论门**：正式 NB/IS/X/Y/A、无效或 FTO 风险判断，仍须具备可定位全文、公开日/基准日核验；FTO 另须具备相应地域的法律状态核验。
- **报告门**：仅在报告定稿时统一核对策略、运行记录、范围声明与报告；如主张完整提取/覆盖，必须补齐相应证明，未补齐则明确限度。

## 五道验证关卡

1. **实在性**：仅列入已通过官方或可信数据库书目核验的公开号/专利号；记录数据库和核验日期。实在性关卡不要求下载或本地保存 PDF。
2. **完整性**：至少具有一组覆盖 CN、US、JP、KR、EP、WO/PCT 的可复现全球统一检索式，记录六语关键词、命中数、日期、结果记录及法域分布或覆盖核验。无需为每个法域分别执行检索式。首次运行后即可筛选核心文献；已知 benchmark 未命中、异常覆盖或疑似截断应触发高风险复核和补检，而非阻断运行。仅在最终报告主张完整提取/覆盖时，才须完成相应分页/分批或法域拆分触发证明；不能完成时，应记录限制，不得声称完整覆盖。缺少任一法域覆盖核验且无缩减授权时，不得将报告表述为六法域完整覆盖。
3. **对比性**：号级或摘要级文献可以列入候选清单，但不得支撑具体技术特征结论。拟作为核心对比文件的文献必须通过 MCP 或可信全文渠道读取内容；仅在能定位到权利要求、段落或附图时标记“充足”。本关卡要求可定位的电子全文证据，不要求下载或本地保存 PDF。
4. **法律状态**：FTO 结论仅使用已通过相应权利地域官方或可信渠道核验法律状态、有效期/届满信息和审查状态的权利；无效检索须核验公开日早于基准日。外观设计是否纳入由产品外观及调研范围决定。
5. **结论强度**：结论不得超过证据强度。不得写“未侵权”或“可无效”；说明检索并非 100% 穷尽、近 18 个月未公开申请不可检索，并建议专业复核。

## 证据包交接

仅 `formal` 的查新/无效案件须读取并更新 `../mbse-patentability-analysis/references/patent-evidence-pack.md` 定义的 `patent_evidence_pack.json`。`quick/standard` 只维护文献和可定位证据，不填写 X/Y/A、NB 或 IS：

- 相似度、语义检索或机器学习排序只用于候选发现，不能作为特征公开、技术启示或法律判断证据；
- `NB` 必须按“单一文献 × 一项权利要求”填写，绝不以多篇文献拼接否定新颖性；
- `IS` 必须以最接近现有技术为主线，记录区别特征、技术效果、客观技术问题、结合动机、兼容性和合理成功预期；
- 未完成可信全文定位的核心事实保持 `Q`，不得直接进入 X/Y 结论。

## 数据库与审查

优先使用已配置的 `global_core_patent_database` MCP Server 开展跨法域专利检索、号码书目核验，以及核心文献的权利要求、说明书和附图内容读取。检索阶段使用 `search_patents`，将中、英、日、韩、法、德六语同义词组合为全球统一查询，默认不加法域限制；需要核实法律状态时使用 `get_patent_legal_status` 或 `legal_data`；核心文献使用服务器可用的全文、权利要求、`pdf` 或 `fulltext_image` 能力读取并定位证据。工具返回内容可直接用于分析，不要求下载或另存本地 PDF。调用前说明查询目的与范围，记录工具名、完整检索式或专利号、查询日期和结果摘要。若结果过多，先使用 MCP 支持的分页或分批参数；确认仍无法完整稳定提取后，方可按法域拆分查询。

六法域使用以下官方渠道交叉核验号码或异常覆盖，不作为默认起手的六次独立检索：中国使用 CNIPA，美国使用 USPTO Patent Public Search/Patent Center，日本使用 J-PlatPat，韩国使用 KIPRIS，欧洲专利使用 Espacenet/European Patent Register，PCT 使用 PATENTSCOPE。`global_core_patent_database` 返回的权利要求、说明书、附图或全文内容可以支持核心文献对比，但必须保留公开号/专利号和可定位位置；其他可信数据库可用于同族、翻译及交叉核验。只有达到拆分触发条件时，才向用户提供按法域执行的可复制检索式、操作步骤和应带回的号码清单或 CSV。只有 MCP/可信渠道无法读取核心文献内容时，才请求用户补充文本或 PDF，且不要求本地长期保存。

对每件文献标注证据等级与来源：`(号级线索: 数据库名/核验日期)`、`(摘要级线索: 数据库名/核验日期)`、`(MCP全文核验: 权利要求/段落/图号)`或`(用户提供)`。号级线索用于候选清单，摘要级线索用于初步排序；核心技术特征结论必须由 MCP 或可信全文定位支持。不得因未下载或未在本地保存 PDF 而降低已经完成的 MCP 全文核验等级。

## 本地分析衔接

当用户已提供或已授权导出的专利语料时，可调用 `$patentkit-local-toolkit` 进行本地候选排序和要素对比。该工具只补充分析，不替代 CNIPA 检索、书目核验或法律状态核验；其结果仍须通过本工作流的五道验证关卡。

## 复核与回退

仅在 `formal` 的工程5/交接前，或出现基准日/范围冲突、疑似截断、异常法域分布、核心证据资格或 FTO 法律状态等高风险触发事项时，使用 [review-prompt.md](references/review-prompt.md) 进行独立复核。BLOCKER 必须解决；HIGH_RISK 写入 `risk_register` 并限制结论强度；DEFERRED 项留待 formal 报告统一完成。若范围、基准日、技术特征或对比结论发生实质变化，回到受影响上游阶段并重置相应证据状态。
