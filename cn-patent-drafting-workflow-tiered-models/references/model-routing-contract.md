# Luna、Terra、Sol模型路由合同

本合同只规定模型工作分工，不改变`protectable-unit-contract.md`、证据包合同、阶段参考文件或代理师确认门。发生冲突时，以事实不编造、状态合同、证据包规则和代理师确认门为准。

## 一、运行模式、路由记录与交接包

运行模式、案件清单、任务上下文、暂存目录及失效规则以`context-and-handoff-contract.md`为准。合同版本为`multi-model-orchestration/2.0`。`advisory`仅表示推荐层级；`orchestrated`必须由控制器执行记录证明真实模型身份。

每个工作项建立一条路由记录：

| 字段 | 要求 |
|---|---|
| `task_id` / `stage` | 唯一工作项及所属阶段 |
| `assigned_tier` / `assigned_model` | 层级为`Luna`、`Terra`或`Sol`；`assigned_model`只能由控制器按固定模型注册表解析 |
| `input_versions` | 输入文件、版本、基准日和可读取范围 |
| `allowed_actions` | 本合同许可的操作 |
| `output_class` | `extraction`、`candidate`、`review`或`approved_draft` |
| `evidence_links` | 原文位置、`CF/EV/DOC`等可回指标识；无定位即`Q` |
| `review_status` | `待复核/已复核/已确认`；只有代理师可确认阶段门 |
| `escalation_reason` | 不确定、冲突、边界改变或需判断时必填 |

下游只能消费已登记的输入版本和输出。Luna输出不得作为事实或法律结论；Terra输出不得直接作为正式申请文件母本；Sol输出仍须经过相应技术确认和代理师确认。所有交接必须引用同一`input_snapshot_hash`。

## 二、模型权限

### Luna：确定性执行层

允许：

- 登记文件、版本、日期、文献号、图号、术语、编号和已有ID；
- 在指定材料内摘录原文并记录页码、段落、权项、图号或稳定锚点；
- 按已给定字段填表、去重、排序、格式转换、生成目录、依赖图和静态检查；
- 根据已冻结文本生成Mermaid/VSDX初稿，或检查编号、引用、术语、版本和字段完整性。

禁止：

- 新建或改变`R/F/S/B/E`、CHAIN、PU、PST、CTX、CF必要性或技术效果；
- 将内容认定为明确公开、现有技术、`[D]`、`[N]`、`[G]`、`admitted`或任何NB/IS结论；
- 概括、补写、改写会扩大技术含义的权利要求或实施方式；
- 对缺失、歧义、冲突或无法定位内容作推断。此类内容只写`proposed_status=Q`或`unverified`并升级至Terra，不得写入正式状态轴。

Luna输出类别只能为`extraction`；其任何“命中”只表示文本匹配或字段匹配，不表示技术或法律判断。

### Terra：受证据约束的候选层

允许：

- 在已定位材料范围内形成R/F/S/B/E、IU、CF/REL/CT/INT、背景技术、实施方式和权利要求的候选结构或预审草案；
- 汇总多文件差异、检索初筛、支持缺口、图文不一致和待确认问题；
- 为已冻结的权利要求特征生成从权、实施例、检索块及附图语义源候选；
- 对Luna结果作语义复核，并产生证据、状态或问题的**建议**。

禁止：

- 确认CHAIN闭合、PU准入、PST客体完整性、CTX组合允许性、独权必要性、单一性、技术效果或可提交性；
- 确认文献的完整公开、最接近现有技术、NB/IS风险、实际技术问题、结合动机或合理成功预期；
- 将建议状态写为正式状态，或把预审草案标为正式母版/提交候选版。

Terra输出类别为`candidate`或`review`。缺少精确定位、存在相互矛盾证据、涉及跨CTX组合或可能改变保护边界时，必须升级至Sol。

### Sol：实质判断与整合层

允许：

- 复核证据并判断F/E边界、技术闭合、CHAIN关系、PU/PST、必要特征、CTX和保护布局；
- 审核全文证据、生成或复核NB/IS、确定新颖性单文献边界、创造性三步法、技术问题、文献组合路径和单一性风险；
- 审核正式母版、提交候选版、背景技术、实施方式、附图语义与阶段8/9实质交付物；
- 决定回退阶段和向代理师提交的待确认事项。

限制：

- Sol不得将无证据内容由`Q`改为已核验，也不得代替发明人/有权技术人员确认`[N]`事实；
- Sol不得代替代理师确认阶段门、形成对外法律承诺或提交申请/答复。

Sol输出可为`approved_draft`或`review`；`approved_draft`只表示通过模型实质审核，仍待代理师确认。

## 三、九阶段路由

| 阶段 | Luna | Terra | Sol |
|---|---|---|---|
| 1 技术建模 | 材料索引、原文定位、术语归一、节点表格式化 | 节点/追溯链候选、待确认问题 | 模型边界、CHAIN独立性、PU/PST/CTX与技术闭合 |
| 2A 查新接口 | `search_context`材料清单和静态检查 | 检索请求候选；不执行检索 | 冻结请求、接收并审核`search_handoff`；检索实质工作归检索Skill |
| 2B 布局 | 判断卡骨架、证据索引和台账 | 候选区别关系、风险问题清单 | NB/IS、单一性、PU准入和保护布局 |
| 3 权利要求 | 编号/引用/术语检查、依赖图静态检查 | 冻结特征的预审草案、从权与实施例候选 | 必要特征、PST、概括边界、母版与提交候选版 |
| 4 背景技术 | 格式和已确认术语检查 | 基于冻结事实的初稿 | 缺陷与技术问题边界、泄露检查、实质审核 |
| 5 实施方式 | 模板、交叉引用、图文编号检查 | 基于已确认特征的初稿与一致性分析 | 充分公开、效果因果、支持范围和实质审核 |
| 6/7 附图 | Mermaid/VSDX初稿、标号同步 | 节点/图元与原文对齐 | 结构、状态、分支和技术关系完整性 |
| 8 审计 | 文本比对、矩阵预填、版本差异扫描 | 缺口与不一致问题清单 | 支持性、问题等级、补强和可提交性意见 |
| 9 交接 | 文件清单、版本链、ID索引 | `oa_context`和待核问题 | 审核`oa_handoff`并回写；答复策略、修改和论证归OA Skill |

## 四、升级与失败安全

Luna遇到以下任一情形，停止判断并以`Q`升级至Terra：无原文定位、术语一词多义、文本冲突、跨文件合并、疑似技术事实或法律含义。

Terra遇到以下任一情形，停止定案并升级至Sol：需要创建/删除/合并CHAIN、PU、PST或必要CF；需要变更任何正式状态；需要选择核心文献或技术问题；需要评估新颖性、创造性、单一性、支持性或修改保护范围；需要让草案进入正式母本。

任何模型发现来源缺失、未确认新增事实、PST边界改变、检索边界改变、CTX组合为`Q/prohibited`、`technical_closure=open/Q`或版本失效时，按原工作流回退规则处理，不得静默修复或继续下游正式交付。

## 五、审校顺序

每份正式候选交付采用：`Luna静态检查 → Terra证据/一致性复核 → Sol实质审核 → 有权技术人员确认新增事实（如有） → 代理师阶段确认`。

最终向用户呈现的申请文件和审查意见答复不得显示内部模型名称、路由记录、ID状态或审核轨迹。
