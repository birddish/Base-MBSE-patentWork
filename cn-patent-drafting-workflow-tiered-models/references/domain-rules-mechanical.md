# 机械/结构域撰写规则

## 规则成熟度说明

本文件处于**初始骨架阶段**。当前机械域沿用通用撰写护栏（`drafting-guardrails.md`）和通用权利要求规则（`stage-3-claim-drafting.md`），以下仅列出机械域特有规则和已识别的规则空白。代理师在各阶段需额外关注 `[待确认]` 标记项。

本域规则在阶段3和阶段5时必读；阶段1 建模时参考本文件的特征类型指导。

## 已确立的机械域特有规则

### 权利要求特征类型

- **产品权利要求**优先采用：结构特征、连接关系、位置关系、配合关系
- **方法权利要求**优先采用：装配步骤、加工步骤、操作步骤
- 禁止功能性限定，除非结构特征无法表达且说明书有充分支持

### 独立权利要求架构

- 必含：基础构件 + 特征性构件 + 连接/配合关系
- 连接关系写明：固定连接/活动连接/传动连接 + 连接方式 + 相对位置
- 避免：仅用功能描述构件（如"固定装置"），须有结构基础

### 从属权利要求分层

推荐层次：核心结构 → 连接细化 → 材料/尺寸 → 附加功能件

每层增加一个可识别的结构特征，对应一项技术效果。

### 实施方式

- 结构主实施例 + 至少一个变体实施例
- 必须描述装配关系或运动关系
- 附图标记与特征逐一对应
- 可采用"权利要求整体 → 结构说明及扩展 → 技术效果"的三块结构适配版

### 附图

- 机械域默认建议 **VSDX 直接建模**（跳过 Mermaid 阶段6），因 Mermaid 无法表达空间结构关系
- 结构图、装配图、剖视图、爆炸图优先用 Visio 绘制
- 若同时有流程图（如控制逻辑），流程图部分仍可用 Mermaid

## 机械域追溯链与权利要求映射约定

机械域追溯链 R→F→S→B→E 的域特定语义：

| 节点 | 机械域语义 | 示例 |
|------|-----------|------|
| **R** | 一级技术问题 | "如何在行进中实现托盘翻转？" |
| **F** | 解决该问题所需的功能（概括） | "翻转功能" |
| **S** | 实现该功能的具体机构 | "翻转机构，包括电磁铁、连杆、转轴" |
| **B** | 机构的使用方式：接收什么输入、发生什么状态转换 | "电磁铁接收通电信号，从释放状态切换为吸合状态，带动连杆使托盘从水平状态切换为翻转状态" |
| **E** | 由结构/行为和输出状态产生的技术作用或可观察效果 | "在连续行进中完成卸料并减少额外停机步骤" |

> 机械域中B与E通常紧密耦合但不是同一对象。B及STATE记录机构如何从初始状态迁移至输出状态；E另行记录该状态或作用路径如何改善释放、密封、承载、定位或可靠性，并保留因果与证据。不得用“到达某位置”同时替代行为、输出状态和技术效果。

### 映射至权利要求

机械域仍须按`CHAIN → PU → PST → 权利要求`派生。通过PST客体完整性和必要特征测试后，独权通常表达F、S、REL、必要IF/CV以及B/STATE；E主要用于必要性测试和说明书因果论证，不因与B相关而被视为同一节点：

```
一种[主题]，用于[解决R]，
  其特征在于，包括：
    [F：一功能模块]，
      所述[F]包括[S1]和[S2]；
    [B：S1接收X输入，从状态A切换为状态B，驱动S2从状态C切换为状态D]。
```

### 机械域特别注意

- 多个子 CI 常共用同一结构体（如一个电磁铁同时驱动翻转和锁定），独立性测试关注**技术问题解决的逻辑闭合性**而非物理构件的独立性
- 仅当状态转换条件对当前PU/PST闭合确属必要且有来源时才进入独权，不得机械省略或机械加入

## 建模指导（阶段1 参考）

机械域的阶段1 建模优先关注：

- **结构分解**：将整体结构按装配层级拆分为构件/组件/零件
- **连接关系**：记录构件间的固定连接、活动连接、传动连接
- **配合关系**：间隙配合、过盈配合、过渡配合
- **运动关系**：转动、滑动、摆动、复合运动
- **力/力矩传递路径**：从动力源到执行端的传递链

以上为建模关注点，具体建模格式仍遵循 `stage-1-mbse-modeling.md` 的通用框架。待 M-Q06 有确认结论后更新。
