# 中国专利审查意见答复与复审意见陈述撰写

## 适用范围

本技能用于中国专利审查意见答复和驳回复审意见陈述书的撰写，覆盖以下三个技术领域（**mode**）：

| Mode | 领域 | 适用案件类型 |
|------|------|-------------|
| `mechanical` | 机械/结构 | 机械结构、装配体、运动机构、传动路径、受力路径、密封、定位、安装、导向结构、制造设备、分拣/物流设备 |
| `biochemical` | 生化/材料 | 化合物、组合物、制备方法、用途发明、生物序列、材料配方、食品/化妆品 |
| `electronic-communication` | 电子通信/AI/软件 | 电子电路、通信系统、信号处理、AI/ML算法、软件方法、天线/射频、网络、控制、数据/信息处理 |

默认首先生成 Markdown 草稿。仅在用户确认 Markdown 文本或明确要求 DOCX 格式后才生成 DOCX 文件。

## 使用方式：主 mode、辅助视角与交付深度

开始时必须记录一个**主 mode**。若材料足以判断，直接推定并在答复假设中说明；只在技术领域存在实质歧义且会改变分析路径时才询问用户。复合技术另记录零个或多个**辅助视角**，但不改变主 mode 的交付结构。

同时记录交付深度：

| 深度 | 适用情形 | 必交内容 |
|---|---|---|
| `compact` | 期限较紧、仅需主要争点 | 准入表、争点表、核心追溯链、权利要求修改稿、答复稿、就绪性审计 |
| `standard` | 默认 | 完整五阶段交付、统一证据包、模型到答复追溯报告 |
| `deep` | 复杂组合、高价值或驳回复审 | `standard` 内容加备选修改方案、多路径压力测试和风险备忘录 |

**Mode 对工作流的影响**：

| 工作流要素 | mechanical | biochemical | electronic-communication |
|-----------|-----------|-------------|--------------------------|
| **S 节点类型** | 构件、连接关系、配合关系、位置关系 | 组分、含量、工艺步骤、工艺条件 | 模块、数据项、信号、算法步骤、协议 |
| **物理机理分析** | 必做（主动力源、受力路径） | 选做（反应机理、结构-性能关系） | 选做（信号流、数据流） |
| **接口兼容性** | 尺寸/节距/运动/受力 | 反应条件/参数范围/组分相容性 | 数据格式/协议/时序/硬件依赖 |
| **论证模式** | 7 种机械论证模式 | 6 种生化论证模式 | 6 种电子通信论证模式 |
| **撰写规则** | 机械域撰写规则 | 生化域撰写规则 | 电子通信域撰写规则 |

## 阶段零：材料、证据与提交准入门

执行五阶段前，读取 `references/intake-and-readiness-gates.md`，建立《案件准入与交付边界表》。必须分别核验：

1. 审查意见/驳回决定、申请文件、全部引证文件是否齐全；
2. 对比文件的公开日、优先权/申请日和新颖性、创造性证据资格是否可核验；
3. 最新权利要求的版本、替代关系和修改支持依据是否确定；
4. 提交期限、申请人/代理信息、补正手续和客户确认项是否齐备。

同时按 `references/version-and-recalculation-gates.md` 建立唯一问题注册表、文献资格表和活动权利要求集合。日期缺失或冲突必须使用 `Q`；`conditional` 仅用于测试材料已经明确记载、但官方材料尚待核验的情况。

材料不齐时允许继续形成“条件性分析稿”，但必须将影响项标记为 `Q`，且不得把结论标注为“可提交”。

## 五阶段递进式工作流

本技能遵循五阶段递进式工作流，各阶段输出作为下一阶段的强制性输入。不得跳过任一阶段直接进入撰写。

```
阶段一：MBSE 建模
  → 申请文件 MBSE 模型 + 各对比文件 MBSE 模型 + 节点对照总表
      ↓
阶段二：事实核实与审计
  → 审查意见事实主张核实表 + 事实核实审计报告
      ↓
阶段三：追溯链与技术启示分析
  → 审查员组合路径追溯链映射 + 结合可能性分析 + 追溯链分析报告
      ↓
阶段四：撰写审查意见答复
  → 审查意见答复书 / 复审意见陈述书（Markdown）
      ↓
阶段五：答复审计
  → 内容正确性审计 + 提交就绪性审计
```

---

### 阶段一：MBSE 建模

对申请文件和每一篇引用对比文件分别进行 MBSE 建模，建立结构化的技术特征模型，作为后续所有事实核实和创造性分析的统一证据基础。

**建模执行**：委托 `mbse-patentability-analysis` 技能（`mode=document`）完成。该技能产出每文件 R/F/S/B/E 节点表、双向追溯矩阵、多文件节点对照总表、审查员逻辑映射表等。

**建模对象**：
- 本申请文件（权利要求书、说明书、附图）；
- 审查员引用的每一篇对比文件（D1、D2……）；
- 审查意见通知书 / 驳回决定中的审查员逻辑。

**必须交付物**（由 `mbse-patentability-analysis` mode=document 产出）：
1. 申请文件 R/F/S/B/E 节点表及追溯链；
2. 每篇对比文件的 R/F/S/B/E 节点表及追溯链；
3. 申请文件与各对比文件的节点对照总表（标明各节点的对应/差异/缺失关系）；
4. 审查员逻辑的 R/F/S/B/E 映射（审查员认定的区别特征 → 对应节点、审查员声称的教导 → 对应追溯链）。

**建模深度要求**（按 mode 差异化）：
- 每项技术特征定位至具体段落或附图标记；
- 追溯链标注独立闭合性（独立闭合 / 需与其他链联合）；
- **mechanical 必做**：对涉及运动/力传递的 F 节点和 B 节点标注主动力来源、辅助力/约束及证据状态；
- **biochemical 选做**：对涉及反应机理的 B 节点标注反应路径、催化剂/酶、中间体及证据状态；
- **electronic-communication 选做**：对涉及数据/信号处理的 F/B 节点标注输入数据格式、处理算法、输出数据格式及证据状态。

**证据状态标记**：`document` 模式的每个节点和关系仅标注 `D`（明确公开）、`I`（受限推断）、`Q`（待确认）或 `X`（排除）。`N/G` 仅用于申请前交底来源，不能作为对比文件或审查意见事实状态。

**证据包交接**：必须读取 `references/oa-evidence-pack-schema.md`，新任务使用 `v2.1-oa`。如存在申请前成果，再对照 `../mbse-patentability-analysis/references/patent-evidence-pack.md` 读取并升级 `patent_evidence_pack.json`。阶段一至五使用同一组稳定 ID，并将问题注册表、活动权利要求集合、分析快照、修改策略、NB/IS、答复追溯和就绪性状态回写。最终答复仅使用对外技术与法律语言，不显示内部 ID、状态标签或流程术语。

阅读 `references/phase-1-mbse-modeling.md` 获取 OA 场景专属的补充指导。

### 阶段二：事实核实与审计

基于阶段一的 MBSE 模型，对审查意见通知书或驳回决定中的每一项事实认定进行逐项核实。**此阶段仅判断事实真伪，不涉及创造性法律结论。**

**核实对象**：
- 审查员对对比文件公开内容的认定（"D1 公开了……"）；
- 审查员对区别特征的认定（"权利要求 1 与 D1 的区别在于……"）；
- 审查员对技术启示的认定（"D2 给出了……的技术启示"）；
- 审查员对公知常识的引用。

**核实方法**：
1. 提取审查意见中的每一项事实主张，编号并录入核实表；
2. 在对比文件和申请文件原文中定位对应的段落、句子或附图标记；
3. 逐项比对审查员的表述与原文，判断是否一致；
4. 对每项主张给出核实结论。

**核实结论分类**：

| 结论 | 含义 | 后续处理 |
|------|------|---------|
| `支持` | 审查员陈述与原文一致 | 可直接作为论证起点 |
| `部分支持` | 审查员陈述部分准确但存在遗漏或过度解读 | 需补充完整上下文，标注偏差点 |
| `不支持` | 审查员陈述与原文矛盾 | 作为重点反驳依据，附原文对照 |
| `无记载` | 审查员引用的内容在对比文件中找不到对应记载 | 标记为事实错误，作为程序性质疑依据 |

**必须交付物**：
1. 审查意见事实主张核实表（逐项编号、审查员原文、对比文件原文定位、核实结论、偏差说明）；
2. 事实核实审计报告（汇总统计、重点争议事项、可用于反驳的事实依据清单）。

阅读 `references/phase-2-fact-audit.md` 获取完整指导。

### 阶段三：追溯链与技术启示分析

基于阶段一的 MBSE 追溯链和阶段二的事实核实结果，对审查员主张的对比文件组合路径进行技术层面的可行性分析。分析方法论基于 `references/mbse-novelty-inventive-step-mapping.md` 定义的六种融合失败模式和四种覆盖缺口。

开始分析前必须冻结唯一 `analysis_snapshot` 和唯一主修改策略；备选策略单独建模，不得进入活动NB/IS或当前核心区别链。快照冻结协议见 `references/version-and-recalculation-gates.md`。

**分析对象**：
- 审查员主张的对比文件组合方式（D1 + D2、D1 + D2 + 公知常识等）；
- 审查员声称的各对比文件教导及其在组合中的作用；
- 审查员声称的技术启示来源。

**必须交付物**：
1. 审查员组合路径的追溯链映射图（标注各节点来源文件）；
2. 结合可行性分析表（六种融合失败模式逐项检查汇总）；
3. 融合链覆盖分析表（四种覆盖缺口逐项检查汇总）；
4. 追溯链分析报告（组合可行性总结、断裂点清单、覆盖缺口清单、可用于反驳的技术论据）。

阅读 `references/phase-3-traceability-analysis.md` 获取完整指导。

**Mode 特定论证模式**：
- mechanical → `references/domain-argument-patterns-mechanical.md`
- biochemical → `references/domain-argument-patterns-biochemical.md`
- electronic-communication → `references/domain-argument-patterns-electronic-communication.md`

### 阶段四：撰写审查意见答复

基于前三阶段的 MBSE 模型、事实审计报告和追溯链分析报告，撰写审查意见答复或复审意见陈述书。

**案件类型判断**：
- 当来源是审查意见通知书时 → 审查意见答复结构；
- 当来源是驳回决定时 → 复审意见陈述书结构；
- 若两者均有 → 以驳回决定为准，同时参考审查历史。

**论证要求**：
- 每个论证点必须有阶段二或阶段三的证据支撑（引用核实结论编号或追溯链断裂点编号）；
- 区别特征分组遵循阶段一中建立的技术路线因果顺序；
- 事实陈述使用阶段二核实为 `支持` 或 `部分支持` 的原文引用；
- 反驳点使用阶段二核实为 `不支持` 或 `无记载` 的事项，附原文对照；
- 技术启示反驳使用阶段三的融合失败模式分析和覆盖缺口分析；
- 不得引入前三阶段未建立的新事实或新论证。
- 先建立“审查意见问题—处理动作”矩阵，处理动作只能为：认可、争辩、修改、删除、分案、补充核验或提请客户确认。
- 权利要求一经修改，必须按“新建版本—支持依据—旧分析失效—活动集合冻结—影响闭包—TA再生成—NB/IS重算—答复追溯切换”的原子事务执行，并通过 `recalculation_gate`；未通过时阶段四只能输出内部条件性草稿，不得定稿。
- 内部工作稿保留可追溯编号；对外答复稿必须将编号转换为完整技术与法律表述。

阅读 `references/phase-4-opinion-drafting.md`、`references/general-workflow.md` 和 `references/reexamination-opinion-framework.md` 获取完整指导。

### 阶段五：答复审计

对完成的审查意见答复或复审意见陈述书进行系统审计，确保论证质量、事实准确性和格式规范。

**审计维度**：
1. **事实一致性审计**：逐项核验答复中的事实陈述是否与阶段二的事实核实报告一致；
2. **论证逻辑审计**：核验每个创造性论证点是否有阶段三的追溯链分析支撑；
3. **权利要求版本审计**：确认引用的权利要求文本为最新版本，无旧版残留；
4. **支持依据审计**：确认每项权利要求修改均有原申请文件支持依据；
5. **措辞审慎性审计**：检查是否有无支持的效果断言或 MBSE 符号残留；
6. **格式与引用审计**：检查段落引用、权利要求编号、对比文件编号的准确性。
7. **问题覆盖审计**：审查意见中每一项问题均有唯一处理动作、证据依据与答复位置；
8. **提交就绪性审计**：将“内容正确性”与“形式可提交性”分别给出状态，并列出剩余阻塞项。
9. **五方一致性审计**：活动权利要求集合、问题注册表、NB/IS、答复段落与就绪状态必须引用同一活动快照并完全对应。

阅读 `references/phase-5-opinion-audit.md` 和 `references/output-checklist.md` 获取完整指导。

## 论证优先级

在有案卷支持的情况下，按以下顺序优先选择论证方式（通用框架，各 mode 有域特定变体）：

1. **技术路线因果关系**：展示问题 → 结构/组分/算法 → 驱动/控制/处理方式 → 效果的完整因果链条。
2. **对比文件不兼容**：解释为何在不改变其工作原理、受力路径/反应路径/数据流的情况下，所引用的技术方案无法组合。
3. **可追溯链条**：将权利要求特征与说明书中记载的问题、功能、结构、行为和效果连接起来。如有 MBSE 文件，将其作为撰写支持，但不得在最终意见陈述书中保留 MBSE 符号。
4. **域特定机理分析**：mechanical → 非直接驱动力分析；biochemical → 反应路径/组分相容性分析；electronic-communication → 数据/信号流分析。
5. **传统替代方案失败**：若审查员的组合建议了某种惯用的已知替代方式，解释为何该惯用替代方式不能解决实际技术问题。

## 输出格式

### 审查意见答复（Markdown 结构）

```markdown
# 审查意见答复

申请号：
申请人：
发明创造名称：

尊敬的审查员：

## 一、修改说明

## 二、关于修改符合专利法第三十三条的说明

## 三、关于独立权利要求具备创造性的意见陈述
### （一）审查员认定的区别特征与组合路径
### （二）实际解决的技术问题
### （三）区别技术特征的划分
### （四）关于区别技术特征一：……
### （五）关于区别技术特征二：……
### （六）区别技术特征的整体协同效果

## 四、关于从属权利要求的创造性

## 五、结论
```


## MBSE 到新颖性/创造性的映射框架

本技能采用 MBSE 五层模型（R/F/S/B/E）作为新颖性和创造性分析的理论基础：

- **新颖性核实** ⇔ 按单一对比文件逐一核对权利要求全部必要 `CF` 的明确或必然隐含披露，并核验公开日和证据位置。
- **创造性答复** ⇔ 先核实最接近现有技术、区别特征与实际技术问题，再核实第二文献/公知常识是否提供结合启示、动机、兼容性及合理成功预期。
- **融合失败/覆盖缺口** ⇔ 工程分析子项，用来支持“缺少技术启示”“存在适配障碍”“效果不可合理预期”或“事实待核验”，不单独构成法律结论。

详细理论框架、各 mode 的融合失败模式判断标准、覆盖缺口分析方法和各域完整示例见 `references/mbse-novelty-inventive-step-mapping.md`。

## 域特定撰写规则

各 mode 的撰写规则详见对应的域规则文件。以下为各 mode 的核心撰写原则摘要：

### Mechanical 模式核心规则

- 以权利要求区别特征及其机械功能为中心展开论证，而非逐文件批评。
- 解释结构如何运作：相对位置、连接、运动、力传递、约束、接触、变形、密封、导向或装配顺序。
- 对于受力路径论证，识别主动力源、接触或啮合区域、直接驱动单元、间接驱动单元、单元间传递路径、约束反力及运动结果。
- 不要将仅基于附图的推论作为权利要求限定。
- 不要将未要求保护的参数（如"大""小""长"）转化为明示的权利要求限定。
- 对推断性优点使用审慎措辞："提供……结构基础""适于……""能够减少/避免……"。
- 详见 `references/domain-rules-mechanical.md`。

### Biochemical 模式核心规则

- 产品权利要求必含必要组分 + 含量范围；区分开放式/封闭式表述。
- 方法权利要求必含步骤顺序 + 工艺条件（温度、时间、压力、pH 等）。
- 注意参数限定的测量方法一致性；范围端点值须有实施例支撑。
- 组合物中组分的相容性分析是创造性论证的核心——分析组分间是否会相互反应、工艺条件是否冲突。
- 注意马库什权利要求、生物序列和"治疗有效量"的特殊规则。
- 详见 `references/domain-rules-biochemical.md`。

### Electronic-Communication 模式核心规则

- 权利要求须体现具体技术领域的输入数据 → 算法处理 → 技术输出数据的技术性链条。
- 避免仅针对抽象数学模型、商业规则或通用信息处理的优化。
- 算法特征仅在处理具有具体技术含义的数据、对技术对象施加约束或改善技术指标时，视为有贡献的特征。
- 注意术语转换：实现表述（API/类名/变量名）→ 权利要求表述（模块/单元/信息）。
- 注意单一侵权主体识别和交底覆盖审查。
- 详见 `references/domain-rules-electronic-communication.md`。

### 通用规则（所有 mode）

- 在使用任何决定性命题之前，执行 `references/evidence-and-inference-control.md` 中的证据关卡。区分"未公开/未给出技术启示"与更强的结论"无法实现"。
- 当某项特征被纳入独立权利要求后，应将其从从属权利要求的贡献分析中移除。
- 如使用 MBSE 文件，在最终意见陈述书中将模型符号转换为完整的技术语言。
- 保留用户指定的术语和特征顺序。
- 当问题在于分组后的权利要求区别特征时，不要孤立地攻击引用对比文件。
- 在论证中引用阶段二核实结论编号和阶段三融合失败模式/覆盖缺口编号，确保每个论证点可追溯至证据基础。
- 修改独立权利要求后，必须以新版本重新生成创造性三步法结论，不得沿用旧版结论。
- 技术内容已成熟不等于文书已可提交；两类状态必须分别报告。
