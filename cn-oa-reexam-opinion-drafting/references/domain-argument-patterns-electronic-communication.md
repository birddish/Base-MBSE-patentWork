# 电子通信/AI/软件域论证模式

有选择地使用以下模式。当事实不支持时，不要强行套用论证模式。

## 1. 数据流断裂

当 D2 的算法/处理模块的输入要求与 D1 系统的输出不匹配时使用。

**分析要素**：
- D1 系统在正常运行中输出什么类型/格式的数据；
- D2 的算法/模块要求什么类型/格式的数据作为输入；
- 不匹配的具体方面：数据类型、数据格式、数据精度、数据维度、数据语义。

**模式**：
> D2 公开的 [算法/处理模块] 以 [类型 X 的数据] 为输入前提，该输入须满足 [条件 A（如格式、精度、维度等）]。而 D1 的系统在其正常工作流程中输出的是 [类型 Y 的数据]，该数据 [不满足/不具备] D2 输入所需的 [条件 A]。将 D2 的方案应用于 D1，本领域技术人员首先需要解决"如何从 D1 的 [类型 Y] 数据转换为 D2 所需的 [类型 X] 数据"这一中间技术问题，而 D1 和 D2 均未公开或教导该转换方案。因此，二者无法直接组合。

**示例**：
- D1 输出模拟信号，D2 算法要求数字离散采样值；
- D1 产生二维图像数据，D2 的模型要求三维点云输入；
- D1 数据为时域波形，D2 处理要求频域特征向量。

## 2. 协议/接口不兼容

当 D1 和 D2 基于不同的通信协议、数据接口或系统架构时使用。

**分析要素**：
- D1 使用的协议/接口/架构；
- D2 依赖的协议/接口/架构；
- 不兼容的具体表现：帧结构不同、信令流程不同、参数定义不同、同步方式不同。

**模式**：
> D1 的 [系统/设备] 基于 [协议/架构 A]，其 [帧结构/信令流程/参数体系] 为 [具体描述]。D2 的技术方案针对 [协议/架构 B] 设计，依赖 [B 特有的字段/机制/参数]。由于 [协议/架构 A] 与 [协议/架构 B] 在 [具体方面] 上存在实质性差异，将 D2 的方案"简单移植"至 D1 的系统中，需要对 D1 的底层协议/架构进行根本性改造，而非仅仅替换一个功能模块。本领域技术人员没有动机在不改变 D1 核心架构的前提下引入 D2 的方案。

**示例**：
- D1 使用 LTE 协议栈，D2 的方案针对 WiFi 的 MAC 层设计；
- D1 为集中式架构，D2 的方案依赖分布式节点间的对等通信；
- D1 的接口为专有总线协议，D2 假定标准 PCIe 接口。

## 3. 算法-硬件不匹配

当 D2 的算法依赖于 D1 系统中不具备的硬件能力时使用。

**分析要素**：
- D2 算法对硬件的隐含假设（计算能力、存储容量、传感器类型、执行器能力）；
- D1 系统实际具备的硬件配置；
- 不匹配的后果：算法无法运行、运行结果错误、实时性不满足。

**模式**：
> D2 的 [算法] 以 [硬件条件 A] 为运行前提——该算法要求 [具体硬件能力，如并行计算单元、特定传感器、专用加速器]。而 D1 的 [设备/系统] 仅配置了 [硬件条件 B]，不具备 [硬件条件 A]。在不升级 D1 硬件的前提下，D2 的算法无法在 D1 上正确执行其核心功能 [功能描述]。本领域技术人员不会将依赖于额外硬件能力的算法引入不满足运行条件的系统中。

**示例**：
- D2 的深度学习模型需要 GPU/NPU 推理，D1 为低功耗 MCU；
- D2 的波束赋形算法依赖多天线阵列，D1 为单天线设备；
- D2 要求微秒级实时响应，D1 的操作系统为非实时 OS。

## 4. 信号/数据处理链中断

当 D2 的某个处理步骤以 D1 处理链中不存在的中间结果为输入时使用。

**分析要素**：
- D1 的完整信号/数据处理链路（各步骤的输入和输出）；
- D2 方案中所需的前置处理结果；
- D1 的处理链路中是否产生该中间结果。

**模式**：
> D2 的 [处理步骤 X] 以 [中间结果 M] 为输入。但 D1 的信号/数据处理链路为 [步骤 1 → 步骤 2 → 步骤 3]，在该链路中并不产生 [中间结果 M]。要将 D2 的 [处理步骤 X] 嵌入 D1 的链路中，本领域技术人员首先需要在 D1 的链路中增加产生 [中间结果 M] 的前置处理步骤，但 D1 和 D2 均未公开如何从 D1 的原始数据生成 [中间结果 M]。因此，D2 的方案无法无缝接入 D1 的处理链路。

**示例**：
- D2 需要信道估计结果作为输入，D1 为非相干检测，不产生信道估计；
- D2 需要已完成图像分割的 ROI，D1 直接输出全图分类结果；
- D2 需要已解调解码的比特流，D1 输出的是软判决似然比。

## 5. 技术领域分离

当 D1 和 D2 分属不同的技术领域，本领域技术人员不会有动机跨领域寻找方案时使用。

**分析要素**：
- D1 所属的技术领域及应用场景；
- D2 所属的技术领域及应用场景；
- 两个领域的技术环境差异：性能指标、约束条件、设计惯例；
- 跨领域寻找方案的合理性。

**模式**：
> D1 涉及 [领域 X] 的 [具体应用 A]，其面临的技术问题为 [问题 X]，本领域技术人员解决该问题时会关注 [领域 X] 内的 [解决方案类型]。D2 虽然公开了类似的数据处理/信号处理手段，但 D2 属于 [领域 Y]，解决的是 [问题 Y]，其所处的技术环境（如 [性能约束/数据特征/系统架构]）与 [领域 X] 存在本质差异。本领域技术人员在面对 [领域 X] 的 [问题 X] 时，没有合理动机跨越技术领域去 [领域 Y] 中寻找解决方案——[领域 Y] 的教导不属于 [领域 X] 技术人员常规参考的范围。

**示例**：
- D1 为卫星通信（关注链路预算、多普勒补偿），D2 为 WiFi 室内定位；
- D1 为医学影像处理（关注诊断准确性），D2 为自动驾驶视觉感知（关注实时性）；
- D1 为基站节能（关注覆盖与功耗平衡），D2 为数据中心温控（关注热力学模型）。

## 6. 技术性缺失论证（针对"智力活动规则"驳回）

当审查员认为权利要求的方案属于"智力活动规则和方法"或"非技术方案"时使用。

**分析要素**：
- 权利要求中技术数据的来源（传感器、接收器、检测器）；
- 算法对技术对象的作用（控制、调节、切换、分配）；
- 算法带来的技术效果（提高信号质量、降低误码率、减少时延、节省功率）。

**模式**：
> 本申请的方法并非抽象的数学运算或商业规则。首先，该方法的输入为 [具体技术数据，如接收信号、传感器读数、信道参数]，该数据是通过 [技术手段，如天线接收、传感器采集] 从物理世界获取的。其次，该方法的核心步骤 [步骤描述] 直接作用于 [技术对象，如发射功率、天线方向、编码方式]，对其施加技术性控制。最后，该方法带来了 [客观技术效果，如信号质量提升、干扰降低、功耗减少]。因此，该方法构成具有技术意义的技术方案，而非单纯的智力活动规则。
