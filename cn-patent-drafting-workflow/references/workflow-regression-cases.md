# CHAIN—PU—PST工作流回归用例

本文件是技能规则变更后的验收测试预期，不是待写入申请文件的技术事实。执行回归时，应以实际用例材料为证据，不得用以下预期反向补足原材料。

## 一、四个正向用例

### 1. 瓶盖

- 三条相互替代且各自技术闭合的CHAIN分别形成PU候选；
- 同一准入PU可以枚举瓶盖部件和饮料容器组合两个PST；单件瓶盖PST如依赖外部瓶口完成破膜，则客体完整性失败，饮料容器PST通过；
- 不得绕过PU/PST形成抽象的“可控破膜”合并独权；
- 如跨方案组合特征，必须有CTX、共同属性和作用依据。

### 2. 食品料理机

- 导流、转停控制分别形成闭合CHAIN和PU；合金路线保留为`technical_closure=open`的缺口记录；
- 合金对象标为`paused`并记录B/E合同补正及检索/既有申请重启条件，不进入本轮母版；
- 转停控制PU可分别评价方法PST与装置PST；PST边界改变时重建受影响IU并补检；
- 三个PU是否共案由阶段2单一性风险审查，不以共同产品直接认定。

### 3. 垃圾箱

- 广告或纯信息内容不能形成技术闭环时，只进入1条`exclusion_records`，事实来源轴和撰写采用轴均标`[X]`，不得形成`PU-X/PST-X`；
- 通风和自卸分别形成PU并接受单一性分组；
- 侧壁通道标为`strengthening_subchain`，只能形成从属限定，不得形成独立PU或计入`open_candidate_count`；
- “一般底板”等上位概括须有可定位的CTX、共同技术属性和作用依据；
- 无组合支持不得以多个实施例分别出现为由进入正式母版。
- 回归计数为2条闭合主链、0条开放候选、1条强化子链、2个PU、5个PST、5个IU、9项母版和2项独权；技术正文可已定位，但法律证据成熟度保持Q。

### 4. 快拆卡箍

- 三条快拆CHAIN保持独立并分别形成PU候选；
- 第三实施例与防滑结构的组合结论为`prohibited`，不得进入任何权利要求；
- 三个产品PST通过策略门形成3项独权；三个方法PST默认保留为`reserved/strategy_review_required`，未确认独立价值、单一实施主体、支持和布局时不得形成独权；
- STATE须区分连接、张紧、释放、触发和主要动力源；
- 输出状态与由其产生的技术效果分别记录。
- 回归计数为3条闭合主链、3个PU、6个PST、12项母版和3项独权，不得自动扩张为15项母版、6项独权。

### 5. 版本化统计断言

- V1旧版母版权项总数分别为`17/14/12/12`；
- V2新版母版权项总数分别为`11/11/9/12`；
- V2独权候选数分别为`3/3/2/3`，合计11项；
- V2工作流分别统计闭合主链、开放候选、强化子链、排除记录和PU候选；不得把排除记录或强化子链计入PU候选；
- 母版权项总数与独权候选数必须分别统计，不得以权项数量减少直接推导方法质量提高。

## 二、阻断性失败用例

### F/E边界判别样例

| 场景 | F | F.Output/OutputState | E |
|---|---|---|---|
| 垃圾箱通风 | 使箱体内外空气交换 | 箱体内形成空气流 | 减少湿气积聚 |
| 食品料理机控制 | 控制刀具周期转停 | 刀具交替进入转动和停止状态 | 在相应参数和物料条件下降低局部温升 |
| 快拆卡箍 | 解除连接件锁定 | 卡箍进入释放状态 | 减少拆卸步骤或作用力，仅在有证据时成立 |
| 温控系统 | 根据温度生成转速指令 | 输出目标转速指令 | 在适用空间和负载下改善温升或功耗状态 |

以上样例只规定角色边界，不为具体案件补充事实。比较型或定量E仍须有比较基线、适用条件和证据。

### F-0 F/E同义反复或因果缺失

输入包括任一情形：`F=实现通风，E=实现了通风`；`F=输出裁决结果，E=实现实时裁决`；E没有S/B/REL/CV因果来源；比较型E没有基线、条件或证据；将OutputState直接复制为E。

预期：效果闭合失败，`technical_closure`不得为`closed`；删除该E、移入F.Output或按Q控制，不得据此形成PU准入或效果论证。

### F-1 依赖图违法

输入：一项多项从属权利要求引用另一项多项从属权利要求。

预期：依赖图硬门失败，阻断提交候选版；不得仅给出非阻断提示。

### F-2 状态越权

输入：`fact_status=[I]`且未经有权技术人员确认，或`drafting_status=[G]`没有[D]/[N]概括对象和共同技术属性。

预期：`drafting_admission`不得为`admitted`，内容不得进入正式母版；代理师的法律/策略确认不能替代技术事实确认。

### F-3 未设置目标项数

输入：未设置`target_claim_count`。

预期：保留完成分组和依赖审计的不限项母版，不得自动执行任何固定数字压缩。若设置目标项数，移除内容必须具有说明书预留、另案候选、暂停或排除去向。

### F-4 跨CTX拼接

输入：组合结论为`prohibited/Q`，或者`conditional`条件尚未满足，但候选组合进入权利要求。

预期：阻断母版或提交候选版；不得以各特征分别具有来源替代特定组合支持。

### F-5 旧IU沿用

输入：PST对象边界或必要特征已经改变，IU仍保存旧`pst_boundary_signature`并标为有效。

预期：旧IU失效，按`IU(PU,PST)=SearchProjection(PU｜PST_boundary)`新建IU并补检。

### F-6 open越级准入

输入：`technical_closure=open`却标为`admitted`或进入正式母版。

预期：阻断；只有列明补正条件时才可作为`conditional`预审对象。

### F-7至F-15 1.2对象与策略门

| 编号 | 输入反例 | 预期阻断 |
|---|---|---|
| F-7 | `technicality=failed`或`drafting_admission=excluded`仍存在于PU | 排除对象不得成为PU |
| F-8 | PST回指已排除或技术性失败PU | 排除对象不得派生PST |
| F-9 | 同一广告同时位于排除台账和PU/PST | 排除台账与保护对象集合冲突 |
| F-10 | `strengthening_subchain`形成PU、独权或计入开放候选 | 强化子链角色越级 |
| F-11 | 策略门为Q/未确认的PST映射为独权 | PST消费策略门失败 |
| F-12 | 方法PST缺少明确实施主体或步骤支持却消费为独权 | 方法PST策略门失败 |
| F-13 | `legal_evidence_maturity=Q`却建立已核验新颖性或创造性结论 | 法律证据成熟度不足 |
| F-14 | 组合进入权项但缺少消费状态或理由 | 组合消费记录缺失 |
| F-15 | 报告称广告未进入PU/PST，但证据包仍有`PU-X/PST-X` | 报告与证据包对象集合不一致 |

### 系统性漂移修复用例

- 多个实施例仅执行件、动力来源、安装位置或参数不同，而R/F/必要S/REL、STATE迁移和E因果路径相同：必须共享同一`main_chain`，不得按实施例数增加PU；
- 产品正常使用动作被改写成方法PST但没有独立步骤、实施主体或边界差异：必须标为文字镜像并阻断独权消费；
- 一项进入母版的从权没有`claim_branch_inventory`记录：阻断；
- 同一PST下相同`semantic_key`被拆成两项从权：阻断；
- 独权重述、正常使用说明或无独立回退价值的细化被消费为从权：阻断；
- 具有不同失效模式、证据位置或独立修改价值的支持分支被无理由合并或遗漏：语义oracle失败。

## 三、统一验收

- 每项独权反向定位至CHAIN、准入PU、PST和CTX；
- 每个暂停或排除PU具有理由和重启/退出条件；
- 每个跨实施例组合具有CTX支持记录；
- 母版分配的每项移除具有明确去向；
- 权利要求依赖图通过形式和语义路径审计。
- 每条闭合CHAIN同时通过功能闭合和效果闭合；F、F.Output、OutputState与E均未混同。
- 未完成阶段2的成果均标为`prereview`和“预审草案”，不得作为正式阶段3交付。
